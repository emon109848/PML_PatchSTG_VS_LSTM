# Implementation: audit_data.py

Source: [audit_data.py](../../src/traffic_prediction/audit_data.py).

`main()` hashes the local files, loads traffic, calls audit_values and
audit_metadata, and saves training-only plots with Matplotlib's Agg backend.
No source file is modified and no data is interpolated or imputed.

## Functions

- `audit_values`: expected shape, real numeric dtype, finite/nonnegative values,
  range, zeros, all-zero frames/sensors, split-level zero summaries and sensor
  nonzero-coverage quantiles. Invalid source readings raise errors.
- `audit_metadata`: required columns, 716 matching rows, nonempty fields, unique
  ID/ID2, finite legal coordinates, District 11, and duplicate-coordinate count.
  It preserves row order and does not claim to prove column pairing.
- `plot_patterns`: fixed sensor positions 0/358/715 for first-week histories,
  nonzero daily training profiles, and coverage around the first zero frame.

## Output

The original [audit report](../../reports/data_audit_v1/README.md) explains the
observed figures and limits. The script prints findings; the Markdown report
was written from the executed run, not automatically generated by the script.

For a deliberate rerun, choose a new output folder:

```bash
python scripts/audit_data.py --output-dir reports/data_audit_v2
```

Existing named plots are not overwritten. Matplotlib is already installed in
pml; the first run used a temporary cache because its default path was unwritable.
Plot sensor selections are illustrative, not performance-selected or statistically
representative. The date attached to all-zero frames is an assumed calendar label.

See [quality/provenance concepts](../concepts/03_data_quality_and_provenance.md).
